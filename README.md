#### КСПЗ — агент иерархической классификации пользовательских запросов

Разработал приложение для иерархической классификации сервисов по пользовательским запросам в банковском контуре. Система работает на чувствительных внутренних данных и классифицирует запросы по дереву категорий, выбирая корректный путь в иерархии.

Данные:

- обучающий / рабочий контур: около 100 000 строк пользовательских запросов;
- тестовая выборка: 15 000 строк;
- F1 по категориям: 82%;
- exact match по полному пути: 62%;
- RSS: около 200 MB;
- нагрузочный тест: 48 req/s;
- inference latency: около 200 ms на запрос.

**Что сделано:**

- Разработал retrieval-based решение для иерархической классификации пользовательских запросов.
- Реализовал гибридный поиск:
  - dense retrieval;
  - BM25;
  - TF-IDF.
- Добавил KNN-поиск по найденным кандидатам.
- Реализовал top-k голосование по каждому каналу.
- Добавил fusion-логику для выбора gold path.
- Построил хранение динамического словаря валидных gold-путей.
- Настроил индексы запросов в Qdrant и OpenSearch.
- Реализовал хранение и синхронизацию данных через PostgreSQL.
- Использовал dense embeddings на GigaChat.
- Реализовал самоактуализацию через API:
  - добавление новых запросов;
  - расширение словаря валидных путей;
  - обновление индексов.

**Исследовательская часть:**

Проверил 6 гипотез качества классификации. Решение эволюционировало от тяжёлого подхода с дообучением `bi-encoder + cross-encoder` к более лёгкой и устойчивой архитектуре на retrieval + KNN + channel fusion.

**Финальная архитектура:**

1. Пользовательский запрос поступает в сервис.
2. Система выполняет гибридный retrieve:
   - dense embeddings;
   - BM25;
   - TF-IDF.
3. По каждому каналу выбираются top-k кандидаты.
4. Выполняется KNN и голосование по кандидатам.
5. Fusion-логика объединяет сигналы каналов.
6. Система выбирает финальный gold path в иерархии.
7. При появлении новых данных словарь путей и индексы могут самоактуализироваться через API.

**Ключевой результат:**  
получилось перейти от тяжёлого ML-пайплайна с дообучением моделей к лёгкому production-ready решению с быстрым inference, низким RSS и хорошей точностью на чувствительных банковских данных.

**Стек:**  
`Python` · `FastAPI` · `Qdrant` · `OpenSearch` · `PostgreSQL` · `GigaChat Embeddings` · `Dense Retrieval` · `BM25` · `TF-IDF` · `KNN` · `Top-k Voting` · `Fusion` · `Hierarchical Classification`
